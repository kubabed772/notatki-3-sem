Kilka uwag

  • Deklaracja klasy nie tworzy obiektów, tylko typ.
  • static const int - składnik wspólny dla wszystkich obiektów.
  • Funkcje składowe są zwykle w jednej kopii dla wszystkich obiektów.
  • Funkcja zdefiniowana w ciele klasy jest inline. Poza klasą: void Address::display(){...}, :: to operator zakresu.
  • int getNumber() const - const po nawiasie: funkcja nie zmienia pól obiektu (chyba że są mutable).
  • Klasę można zadeklarować nawet wewnątrz funkcji.

Konstruktor i destruktor

egzamin 2025 · destruktor

Konstruktor

  • Inicjuje składniki. Najlepiej przez listę inicjacyjną: Circle(double r) : radius(r) {}
  • Można mieć wiele konstruktorów (przeładowanie). W klasie jest zawsze co najmniej konstruktor domniemany.
  • Pole można zainicjować w deklaracji - tę wartość weźmie konstruktor domniemany.
  • Pole będące obiektem innej klasy inicjujesz wywołaniem jego konstruktora na liście inicjacyjnej (Cylinder i Circle niżej).
  • Konstruktor delegujący (C++11): wywołuje inny konstruktor tej samej klasy na liście inicjacyjnej.
class Cylinder {
  double height; Circle base;     // obiekt klasy Circle
public:
  Cylinder(double h, double r) : height(h), base(r) {}
  double volume() {return height * base.area();}
};
Cylinder column(10,20);           // albo column{10,20}

Circle nie ma konstruktora bez argumentów, więc base musi być na liście inicjacyjnej. Przypisanie w ciele konstruktora się nie skompiluje.

Tyszer powtarza to dwa razy na slajdach: destruktor nie likwiduje obiektu, tylko wykonuje czynności przed jego usunięciem.

Kolejność

Tworzenie: konstruktory od klasy najstarszej w hierarchii (baza -> pochodna). Usuwanie: destruktory odwrotnie (pochodna -> baza).

Konwersje: konstruktor jako konwerter i funkcja konwertująca

Obcy typ -> moja klasa: konstruktor

Complex (double r = 0.0, double i = 0.0) : re(r), im(i) {}
result = cSum(argument, 2.5);     // OK: 2.5 -> Complex(2.5, 0)

Dzięki argumentom domniemanym konstruktor da się wywołać z jednym double, więc działa jak konwersja double -> Complex. Bez nich (Complex(double r, double i)) wywołanie cSum(Z1, 1.7) to błąd i trzeba by pisać osobne wersje cSum(Complex, double), cSum(double, Complex)...

Moja klasa -> obcy typ: funkcja konwertująca

operator int () {     // bez argumentów i bez typu wyniku
  return int(re);     // część rzeczywista jako int
}

Nie ma argumentów, więc nie da się jej przeładować. Typ wyniku wynika z nazwy (int).

Funkcje zaprzyjaźnione

egzamin 2024 · uzupełnij friend
class B;                          // deklaracja zapowiadająca
class A { public: int reader(B); };
class B {
  int number;                     // prywatne
  friend int A::reader(B);        // funkcja z klasy A
};
int A::reader(B object){ return object.number; }

Przyjaciel ma dostęp do private i protected, ale nie jest składnikiem klasy. friend wpisuje się w klasie, która udostępnia dane (tu B).

  • Klasa B może zaprzyjaźnić się ze wszystkimi funkcjami klasy A (friend class A;) - wtedy A jest przyjacielem B.
  • Przyjaciel mojego przyjaciela NIE jest moim przyjacielem (przyjaźń nie jest przechodnia).
  • Przyjaźń nie jest dziedziczna: przyjaciel klasy bazowej nie ma dostępu do chronionych składników klasy pochodnej.
  • Typowe użycie: friend Complex operator+(Complex, Complex); - operator spoza klasy, który czyta prywatne re, im.

Typowy błąd: operator+(int, double) - oba typy wbudowane, nie wolno.

friend Complex operator+ (Complex, Complex);   // w klasie
Complex operator+ (Complex a1, Complex a2){
  return Complex(a1.re + a2.re, a1.im + a2.im);
}

W klasie czy poza klasą?

  • Operator zmienia obiekt, na którym działa -> składnik klasy: =, ++, +=, *=...
  • Nie zmienia -> poza klasą (zwykle friend): + - * / & !...
  • Operator - funkcja składowa ma o jeden argument mniej (lewy argument to this).
  • Muszą być składowymi: = [ ] ( ) ->
  • Predefiniowane dla każdej klasy: =, & (adres), przecinek, new, delete.
Complex Complex::operator+ (Complex a1){   // składowa: 1 argument
  return Complex(re + a1.re, im + a1.im);
}
Complex result = second + argument;    // BŁĄD, second to double:
                                       // double nie ma operator+(Complex)

Dlatego + robi się poza klasą: wtedy działa też 2.5 + z (konwersja przez konstruktor).

Dziedziczenie

egzamin 2023, 2025 · tryby dziedziczenia

Co widzi klasa pochodna (bez przyjaźni)

w baziepublicprotectedprivate
publicpublicprotectedprivate
protectedprotectedprotectedprivate
privateniedostępne w każdym trybie

Kolumny to forma dziedziczenia (class Car : public Vehicle). Forma obniża dostęp do swojego poziomu, nigdy nie podwyższa.

private a protected: w obu przypadkach klasa pochodna sama widzi public i protected z bazy. Różnica jest dalej: przy protected te składniki są dalej widoczne w kolejnych klasach pochodnych, przy private już nie.

  • Klasa bazowa = uogólnienie, pochodne = specjalizacje. Zwykle tworzy się obiekty klas pochodnych.
  • Pojedyncze: jedna baza (hierarchia jak drzewo). Wielokrotne: kilka baz, class Motorcycle : public Vehicle, public Bike (hierarchia jak graf).
  • Konstruktory baz wołane od najstarszej klasy; te z argumentami podajesz na liście inicjacyjnej: MagicHorse(char m1, char m2) : Horse(m1), msc(m2)
  • Składniki o tej samej nazwie z różnych baz rozróżnia ::.
  • protected daje pochodnym (i ich przyjaciołom) dostęp do "pół-prywatnych" składników bazy.
  • class X final (C++11) - z tej klasy nie można już dziedziczyć.

Polimorfizm i funkcje wirtualne

egzamin 2020, 2023, 2024 · "co wypisze"
Vehicle *p = new Car;      // wskaźnik na bazę może wskazywać pochodną
p->start();
// bez virtual w Vehicle:  "Starting a vehicle."  (decyduje typ WSKAŹNIKA)
// z virtual w Vehicle:    "Starting a car."      (decyduje typ OBIEKTU)
  • Funkcja wirtualna: ta sama nazwa, typ wyniku i sygnatura w bazie i pochodnej; wersja zależy od obiektu.
  • virtual w bazie; w pochodnej można dopisać override (kompilator sprawdzi, że coś przesłaniasz), final blokuje dalsze przesłanianie.
  • Czysta funkcja wirtualna virtual double sum(int) = 0; -> klasa abstrakcyjna: nie da się utworzyć jej obiektu (wskaźnik można).
  • obiekt.Baza::funkcja() wymusza wersję z bazy, mimo virtual.

Przepis na "co wypisze" z Baza *ptr = new Pochodna(...)

1

new: konstruktory od najstarszej klasy w dół, każdy wypisuje swoje.

2

ptr->f(): f wirtualna w bazie -> wersja z klasy obiektu (najniższej). Niewirtualna -> z klasy wskaźnika.

3

delete ptr: sprawdź, czy destruktor klasy wskaźnika jest wirtualny. Tak -> destruktory od dołu do góry. Nie -> tylko destruktor klasy wskaźnika (formalnie UB).

Pułapka z 2024: Animal nie ma wirtualnego destruktora, a Horse ma. Liczy się klasa wskaźnika, czyli Animal, więc żaden z wypisujących destruktorów się nie wykona. Całość w fiszkach.

Wskaźniki, new i delete

egzamin 2025 · co przechowuje wskaźnik
  • Zmienna wskaźnikowa przechowuje adres obiektu danego typu. &x daje adres, *p wartość spod adresu.
  • new tworzy obiekt dynamicznie: bez nazwy, nie obowiązują go zasady zakresu, żyje do delete.
  • Wyciek pamięci: więcej new niż delete.
  • nullptr pasuje do wskaźnika dowolnego typu.
  • Wskaźnik do obiektu: (*p).get() to samo co p->get().
int *ptr = new int;  *ptr = 7;       // dobrze
int *ptr = 7;                        // błąd: int to nie adres
int *ptr;  *ptr = 7;                 // kompiluje się, ale pisze pod losowy adres

Tablice i funkcje

double *v = new double[size];   // nazwa tablicy = adres 1. elementu
v[5] = 33;   *(v + 5) = 33;         // to samo
delete [] v;                        // [] przy tablicy!

double **m = new double *[size1];   // 2D: tablica wskaźników
for (int i = 0; i < size1; i++)
  m[i] = new double[size2];

int (*fun_Ptr)(double, int);        // wskaźnik na funkcję
fun_Ptr = my_function;              // nazwa funkcji = jej adres
(*fun_Ptr)(25.0, 3);
int *fun_Ptr(double, int);          // częsty błąd: to FUNKCJA zwracająca int*

Wskaźnik do funkcji pozwala przekazać funkcję jako parametr innej funkcji. Rodowód (Person *father, *mother) to struktura rekurencyjna na wskaźnikach.

Konstruktor kopiujący i przenoszący

egzamin 2023, 2024

Kopiujący: Klasa(const Klasa &original)

  • Kopia powstaje niejawnie przy przekazaniu argumentu przez wartość i przy zwracaniu obiektu z funkcji.
  • Parametr musi być przez referencję. Przez wartość -> żeby zrobić lokalną kopię argumentu, trzeba wywołać konstruktor kopiujący, który znowu potrzebuje kopii... nieskończona rekurencja.
  • Domyślny kopiujący (i przypisanie) kopiuje pole po polu. Przy polach-wskaźnikach to zła kopia: dwa obiekty na tę samą tablicę ("kto ją usunie?"). C++11: można go zablokować = delete.
Complex::Complex(const Complex &c){ re = c.re; im = c.im; }

Vector::Vector(const Vector &original){
  size = original.size;
  ptr = new double[size];           // własna, nowa tablica
  for (int i = 0; i < size; i++) ptr[i] = original.ptr[i];
}

Przenoszący (C++11): Klasa(Klasa &&original)

  • && = referencja do r-wartości (obiektu tymczasowego).
  • Zamiast kopiować dane, "kradnie" wskaźnik obiektu tymczasowego. Szybkie, bo bez kopiowania tablicy.
  • Po przeniesieniu źródło dostaje nullptr i size = 0, żeby nie było podwójnego dostępu (i podwójnego delete).
Vector::Vector(Vector &&original){
  size = original.size;
  ptr = original.ptr;               // "steal" data
  original.ptr = nullptr;
  original.size = 0;
}

Wskaźniki inteligentne (C++11)

unique_ptr

Jedyny właściciel. Obiekt usuwany automatycznie, gdy wskaźnik znika (np. przy wcześniejszym return, gdzie zwykły new by wyciekł).

auto p1 = make_unique<int[]>(135);
unique_ptr<int[]> p2 = p1;     // BŁĄD: kopia
Compute(p1);                   // BŁĄD: przez wartość
unique_ptr<int> p4(move(p3));  // OK: przekazanie

Własność można przekazać, nie współdzielić.

shared_ptr

Współdzielona własność z licznikiem referencji (use_count()). Licznik = 0 -> obiekt usunięty ("ostatni gasi światło").

auto p3 = make_shared<int>();
shared_ptr<int> p5 = p3;       // OK, licznik 2

Zakleszczenie: A trzyma shared_ptr<B>, B trzyma shared_ptr<A>. Po wyjściu z funkcji liczniki są 1, nie 0, więc nic się nie usuwa.

weak_ptr (miękki)

Współdzieli bez podbijania licznika. Zawsze razem z shared_ptr; przed dostępem trzeba go zamienić na shared.

auto p1 = make_shared<int>(58);
weak_ptr<int> p2(p1);          // licznik dalej 1
shared_ptr<int> p4(p2);        // teraz dostęp
if (p2.expired()) ...          // czy obiekt jeszcze jest

Rozwiązuje zakleszczenie: jedna ze stron cyklu trzyma weak_ptr.

Wzorce klas i pojemniki

podstawa pod listy, drzewa i iteratory z kolejnych wykładów
template <class Item> class Object {
  Item leftNode, rightNode;
public:
  Object(Item, Item);
};
template <class Item> Object<Item>::Object(Item l, Item r)
  : leftNode(l), rightNode(r) {}
Object<int> integerPair(3,5);

Wzorzec pozwala zbudować abstrakcyjną strukturę danych na dowolnym typie. Przy definicji poza klasą za każdym razem template <class T> i Klasa<T>::.

Pojemniki STL

Obiekty przechowujące obiekty innej klasy i zarządzające nimi: wektory, listy, talie (deque), zbiory, stosy, kolejki i kolejki priorytetowe.

Vector<T> i BoundedVector<T> ze slajdów

  • Pola T *data; unsigned size; w sekcji protected (żeby pochodna je widziała).
  • Destruktor virtual ~Vector(): delete [] data; data = nullptr; size = 0; - virtual, bo obiekty pochodne mogą być usuwane przez wskaźnik na bazę.
  • T & operator[](unsigned) const zwraca referencję, żeby element mógł stać po lewej stronie przypisania (v[3] = 5). Środek: assert(index < size).
  • setSize: nowa tablica, przepisz min(stary, nowy) elementów, resztę initial, delete [] data.
  • BoundedVector dziedziczy po Vector<T>, dodaje const int lowBound - indeksy od dowolnej (też ujemnej) liczby.
T & BoundedVector<T>::operator[](int index) const {
  return Vector<T>::operator[](index - lowBound);
}  // bez Vector<T>:: wywołałby sam siebie (rekurencja)

BoundedVector<int> counts('a', 'z', zero);  // 26 liczników
counts[c]++;                               // histogram liter
